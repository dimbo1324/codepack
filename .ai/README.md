# AI Assistant Rule Modules

Single source of truth for the rules that govern every AI assistant (Claude Code,
Codex, and any future agent) working in this repository.

## How it works

```text
.ai/universal/*.md   Portable rules. Valid for ANY project. Never mention project
                     names, paths, or stack specifics.
.ai/project/*.md     Rules specific to THIS project: repo map, commands, domain
                     guardrails, progress tracking, legacy reference.
CLAUDE.md            Thin entry point for Claude Code. Imports every module via
                     native @path syntax.
AGENTS.md            Entry point for Codex. GENERATED by concatenating the same
                     modules (Codex has no import mechanism). Never edit by hand.
.ai/CHANGELOG.md     History of rule changes: what changed, why, and when.
```

Modules load in filename order: `universal/01..NN` first, then `project/10..NN`.
Later content overrides earlier content, so project rules win over universal rules
when they conflict (for example, a stricter file-size limit).

## Editing rules

1. Edit or add a module under `.ai/universal/` or `.ai/project/`.
2. Record the change in `.ai/CHANGELOG.md`.
3. Regenerate the Codex entry point: `cargo xtask sync-agents`.
4. Commit the module, the changelog entry, and the regenerated `AGENTS.md` together.

Never edit `AGENTS.md` directly — it carries a generated-file banner and any manual
edit is lost on the next sync. `CLAUDE.md` needs no regeneration; Claude Code resolves
`@` imports at session start.

The full protocol for changing rules — when it is allowed, who decides, how conflicts
are resolved — lives in `universal/08-rules-evolution.md`. Read it before touching
any module.

## Size budget and module tiers

Codex reads at most 32 KiB of project instructions. The sync script fails if the
assembled `AGENTS.md` exceeds 30 KiB.

Two tiers exist for when the budget gets tight:

- **inline** (default) — the module is embedded in `AGENTS.md` in full.
- **extended** — only the module's title, path, and a one-line essence are embedded.
  Opt in with a marker in the first few lines of the file:

  ```markdown
  <!-- tier: extended -->
  ```

  An extended module MUST carry an essence line right after its title:

  ```markdown
  > **Essence.** One sentence covering the module's core rules.
  ```

Split principle: **inline** is what an agent must know before reading anything else
(orientation, process, constraints that prevent irreversible harm). **extended** is
refinement read when a task touches it.

Extended rules are binding exactly like inline ones — skipping them is a violation,
not a choice. `CLAUDE.md` imports every module regardless of tier, so Claude Code
always sees full detail.

All modules are currently `inline` and the assembled file fits the budget with room
to spare. Reach for `extended` only when the budget actually forces it.

## Porting to another project

1. Copy `.ai/universal/` unchanged.
2. Copy `CLAUDE.md` and the `xtask` sync-agents command; adjust paths if the layout differs.
3. Rewrite everything under `.ai/project/` for the new project.
4. Run `cargo xtask sync-agents` to produce the new `AGENTS.md`.

Keep universal modules genuinely universal: if a rule needs a project path or a
project command to make sense, it belongs in `.ai/project/`.
