# ROADMAP — этапы реализации codepack на стеке Rust + Tauri

> **Назначение файла.** Это план: **что** строим, **в каком порядке** и **что уже готово**.
> Спецификация «что это за продукт и как он устроен» — в [BLUEPRINT.md](BLUEPRINT.md).
> Правила работы ИИ-агентов — в [AGENTS.md](AGENTS.md) / [CLAUDE.md](CLAUDE.md).
>
> **Этот файл — источник правды о прогрессе.** Любой агент в новой сессии определяет
> текущую точку проекта именно отсюда.

- **Проект:** codepack (ранее Project Exporter Desktop 1.0.1, Python/PySide6, только Windows)
- **Новый стек:** Rust (ядро) · Tauri (десктоп) · TypeScript (UI) · SQLite · Win/macOS/Linux
- **Старая реализация:** `docs/__arch__/codepack-main.zip` — эталон поведения (см. §5)
- **Режим разработки:** ~90% задач выполняют ИИ-агенты

## 0. Как пользоваться этим файлом

### Конвенция статусов

У каждого этапа под заголовком может стоять строка статуса:

```text
**Status.** <что именно сдано: крейты, модули, команды, тесты> — <дата>
```

- Этап **со строкой `**Status.**`** — сделан.
- **Первый этап без строки `**Status.**`** — следующий в работе.
- Частичная готовность отмечается так же, но с честным перечнем того, что **не** вошло.

### Порядок обязателен

Этапы идут `S0 → S1 → … → S14`. Начинать поздний этап раньше его зависимостей —
**только по явному решению владельца**, зафиксированному в
`docs/decisions/open-questions.md`.

### Что значит «этап сделан»

Все пункты «Готово, когда» выполнены, качественный гейт зелёный, документы состояния
обновлены (`docs/architecture/overview.md`), строка `**Status.**` добавлена сюда.

### S1 — Доменные типы и конфигурация (`codepack-core`)

**Цель.** Общий словарь для всех остальных крейтов.

**Состав.**
- Типы: `ExportPaths`, `CopyStats`, `TextDumpStats`, `RiskPreviewReport`, `ArchiveBuildResult`.
- `Config` — **все 26 полей** старой версии (BLUEPRINT §A.3) с нормализацией и дефолтами.
- Миграция legacy-настроек (`~/.project_exporter_desktop.json` → новый формат).
- Абстракции сквозной инфраструктуры: канал прогресса/лога, токен отмены (`CancellationToken`).
- Кроссплатформенные пути (BLUEPRINT §D.4) через `directories`.
- Типы ошибок (`thiserror`), единая `Result`.

**Готово, когда.**
- Юнит-тесты на нормализацию всех полей и откат к безопасным дефолтам.
- Round-trip сериализации конфигурации.
- Импорт legacy-JSON проверен на реальном файле старой версии.

### S2 — Сканер: обход, ignore, детект стека (`codepack-scanner`)

**Цель.** Определить, **какие файлы вообще участвуют** в экспорте.

**Состав.**
- Параллельный обход дерева (`ignore`/`walkdir` + `rayon`), без следования симлинкам.
- Базовый набор `IGNORED_DIR_NAMES` (18 имён, BLUEPRINT §A).
- Парсер `.exportignore`: gitignore-подобный синтаксис, каталоги `dir/`, отрицания `!`,
  glob-паттерны, `always_include` файлы/каталоги.
- Детектор стека: **12 стеков** (Node, Python, Go, Rust, Maven, Gradle, .NET, Flutter,
  Composer, Ruby, Swift, Android) + слияние их доп. исключений.
- Классификация текст/бинарь: `TEXT_EXTENSIONS`, `BINARY_EXTENSIONS`,
  `TEXT_FILENAMES_WITHOUT_EXTENSION`, эвристика по NUL/control-байтам.
- Инвентаризация и построение плана экспорта (`28_export_plan.json/.md`).

**Готово, когда.**
- Golden-тесты: план экспорта совпадает с эталоном старой версии на фикстурах
  (минимум по одному проекту на стек).
- Property-тесты правил ignore (включение всегда сильнее исключения).

### S3 — Безопасность (`codepack-security`) ⭐ ядро ценности продукта

**Цель.** Не дать секретам утечь. Это главный этап всего проекта.

**Состав — сначала паритет.**
- Три режима: `safe` / `balanced` / `full` с точными наборами суффиксов и имён (BLUEPRINT §A.4.1).
- Правило `.env` vs `.env.example` / `.env.sample`.
- Редактирование секретов в содержимом (`<REDACTED>`), действует и для буфера обмена.
- Эвристический сканер v3: sensitive-файлы, secret-подобные строки (4 уровня уверенности),
  рисковые паттерны кода (9 правил), самозащита сканера от собственных паттернов.
- Выходы: человекочитаемый `.txt`, `.json`, **SARIF 2.1.0**.

**Состав — затем новое (🎯 BLUEPRINT §B.1).**
- 🎯 Провайдер-специфичные сигнатуры: AWS `AKIA…`, GitHub `ghp_/gho_/github_pat_`,
  Google `AIza…`, Slack `xox[baprs]-`, Stripe `sk_live_/rk_live_`, OpenAI `sk-`,
  Anthropic `sk-ant-`, Telegram bot, JWT `eyJ…`, PEM-ключи.
- 🎯 Энтропия Шеннона (BLUEPRINT §E.2): порог ~4.0 бит/символ для base64-подобных (длина ≥20),
  ~3.0 для hex (длина ≥32) + проверка алфавита и контекста.
- 🎯 Предфильтр `aho-corasick` перед регулярками (производительность).
- **Никакой сетевой валидации секретов** — приватность абсолютна.

**Готово, когда.**
- Паритет: находки на фикстурах совпадают с эталоном старой версии.
- Корпус-тесты: precision/recall/F1 (BLUEPRINT §E.3) на наборе замаскированных
  реальных форматов токенов; recall вырос, precision не упал.
- SARIF валиден по схеме 2.1.0.

### S4 — Diff и снапшоты (`codepack-diff`)

**Цель.** Экспортировать только изменения.

**Состав.**
- 4 режима: `all`, `last_export`, `git_ref`, `uncommitted`.
- Git через **`git2` (libgit2)** — без вызова внешнего процесса (устраняет зависимость
  от установленного git и проблемы парсинга вывода).
- Снапшот проекта: потоковый SHA-256 (чанки 1 МБ), `size`, `loc`, `mtime_ns`.
- Корректная обработка переименований, удалений, путей с пробелами/юникодом.
- Отчёт `29_export_comparison_report.md`.

**Готово, когда.**
- Тесты всех 4 режимов на временных git-репозиториях.
- Отменённый/ошибочный прогон **не** перезаписывает базлайн (регрессионный тест).

### S5 — Хранилище SQLite (`codepack-storage`)

**Цель.** Заменить плоские JSON на настоящую БД (BLUEPRINT §D).

**Состав.**
- Схема: `project`, `export_run`, `run_file`, `finding`, `archive_part`, `snapshot`,
  `snapshot_file` + `schema_version`.
- `PRAGMA foreign_keys=ON`, `journal_mode=WAL`, батч-вставки снапшотов в одной транзакции.
- Индексы по BLUEPRINT §D.3.
- Миграции (нумерованные, необратимые не применяются без анализа рисков).
- **Импорт legacy-истории** из JSON старой версии.
- Политика ретеншна: хранить последние N прогонов на проект.

**Готово, когда.**
- Тесты миграций на чистой и на заполненной БД.
- Импорт legacy-JSON проверен.
- Конкурентный доступ (две сессии) не приводит к порче данных.

### S6 — Байты, токены, бюджет (`codepack-tokens`)

**Цель.** Точная оценка объёма — и в байтах, и в токенах.

> **Жёсткое требование владельца:** байты остаются везде, где они были.
> Токены — **дополнение**, а не замена.

**Состав.**
- Байтовые размеры и `format_bytes` — поведение сохраняется 1:1.
- Оценка токенов: базовая формула `T ≈ B / 3.5` сохраняется как fallback.
- 🎯 Уточнённая модель с калибровкой (BLUEPRINT §E.1): `T ≈ B / (b · k)`, где `b` —
  байт/символ (ASCII ≈1.0, кириллица UTF-8 ≈1.9), `k` — символов/токен.
- 🎯 Пофайловая оценка токенов (для предпросмотра).
- 🎯 `MODEL_CONTEXT_LIMITS` выносится в **обновляемый JSON** (без пересборки приложения).
- 🎯 Режим **Fit to budget** — жадный отбор по плотности ценности (BLUEPRINT §E.5).

**Готово, когда.**
- Байтовые значения побайтово совпадают со старой версией (регрессионный тест).
- Отбор под бюджет детерминирован и объясним («почему включён этот файл»).

### S8 — Архивация (`codepack-archive`)

**Цель.** Собрать итоговый ZIP или набор частей.

**Состав.**
- ZIP deflate уровень 6; жёсткий лимит части 512 МБ, цель 500 МБ, резерв 8 МБ.
- Логическая группировка файлов (13 групп, BLUEPRINT §A.8).
- Разбиение на части + пересборка, если одиночный ZIP превысил лимит после записи.
- `ARCHIVE_SET_MANIFEST.json`, `RESTORE_INSTRUCTIONS.md`, скрипт восстановления
  с **защитой от path-traversal**.
- Отчёт `27_archive_plan.md/.json`.
- 🎯 Опционально: First-Fit Decreasing вместо First-Fit (BLUEPRINT §E.4).

**Готово, когда.**
- Тесты: одиночный ZIP, split-набор, round-trip восстановления.
- Тест безопасности: злонамеренный путь в архиве отвергается.

### S9 — Движок-оркестратор (`codepack-engine`)

**Цель.** Собрать всё в конвейер из 8 шагов.

**Состав.**
- Пайплайн BLUEPRINT §A.2: план → копирование → структура → Git → текстовый дамп →
  аналитика → манифест → архив.
- Контекст разработчика в шапке текстового дампа.
- Прогресс/лог через канал; отмена между шагами и внутри параллельных циклов.
- Запись истории и снапшота (только при успешном прогоне).
- Удаление staging (если не включено сохранение).
- Пользовательские переопределения включения/исключения файлов.

**Готово, когда.**
- Полный экспорт на наборе фикстур совпадает с эталоном старой версии (golden).
- Отмена на каждом из 8 шагов корректно останавливает работу и не портит базлайн.
- Прогон на «тяжёлом» проекте (≥50k файлов) укладывается в бюджет производительности.

## 4. Транши «Ценность» и «Релиз»

### S12 — Человеко-ориентированные результаты 🎯

**Цель.** Результат полезен не только ИИ, но и людям — от джуна до нетехнического специалиста.

**Состав** (BLUEPRINT §B.9).
- Отчёт-обзор «Что это за проект» (HTML/PDF) для техлида и заказчика.
- Секция «Объясни простыми словами» в дашборде.
- Режим ревью для команды: акцент на изменениях + чек-лист ревьюера + ссылки `файл:строка`.
- Онбординг-трек: маршрут «с чего начать читать проект».
- Интерактивный дашборд: фильтры, поиск, отрисовка Mermaid-графа.
- Экспорт диаграмм в SVG/PNG.

**Готово, когда.** Человек без доступа к коду понимает по отчёту, что за проект,
насколько он здоров и где риски.

### S13 — Прямая интеграция с ИИ 🎯

**Цель.** Замкнуть цикл «экспорт → ответ ИИ» без ручного копипаста.

**Состав** (BLUEPRINT §B.8).
- Отправка собранного контекста в выбранную модель **по явному действию пользователя**.
- Ключи API — только в защищённом хранилище ОС (`keyring`), никогда в файлах настроек.
- Полностью отключаемо; приватность по умолчанию (без сети).

**Готово, когда.** Сеть не используется ни при каком сценарии, кроме явно инициированной
пользователем отправки; ключ не попадает в логи, историю и экспорт.

### S14 — Упаковка, подпись, дистрибуция

**Цель.** Установка в один клик на трёх ОС.

**Состав.**
- Tauri bundler: MSI/NSIS (Windows), DMG (macOS), AppImage/deb (Linux).
- Подпись кода (Windows) и нотаризация (macOS) — снимает предупреждения ОС.
- `SHA256SUMS.txt` и релизные артефакты.
- Авто-обновление (опционально, по решению владельца).

## 7. Сквозные требования (действуют на каждом этапе)

- **Приватность.** Никаких сетевых обращений, кроме S13 и только по явному действию.
- **Неизменность источника.** Папка исходного проекта никогда не модифицируется.
- **Отменяемость.** Любая длительная операция прерывается без порчи состояния.
- **Golden-эталоны.** Внешние форматы (BLUEPRINT §D.5) обратно совместимы;
  изменение формата — только с повышением `schema_version` и записью в решениях.
- **Производительность.** Параллелизм там, где есть I/O+CPU нагрузка; потоковая обработка
  больших файлов; UI никогда не блокируется.
- **Тесты.** Новый код покрывается; тесты не удаляются и не ослабляются ради зелёного гейта.
